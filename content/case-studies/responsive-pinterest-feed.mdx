# Responsive Masonry Feed

A masonry layout arranges variable-height items into columns with no fixed boundaries. 
These items of varying heights are packed into columns to eliminate vertical gaps,
resembling stacked bricks. This layout is commonly used for image grids, 
such as those on Pinterest or photo gallery websites.

## Problem Statement

Build an API-backed masonry image feed that adapts to container width, fills
tall viewports automatically, handles slow or failed images gracefully, and
keeps scroll performance stable as the feed grows.

## Requirements

- Render variable-height image cards in responsive columns.
- Load more pins as the user approaches the end of the feed.
- Keep the layout stable while images load or fail.
- Support mobile, tablet, desktop, and container resize behavior.
- Preserve scroll and route state when users open and return from a pin detail page.

## Architecture

- Page shell owns route and navigation boundaries.
- Feed client owns pagination, measurement, loading, and rendered pins.
- `/api/pins` returns paginated pin records.
- The masonry engine turns raw pins into `left`, `top`, `width`, and `height`.

## Masonry Algorithm

```ts
count = max(1, floor((containerWidth + gap) / (minColumnWidth + gap)))
columnWidth = (containerWidth - (count - 1) * gap) / count
shortestColumn = indexOf(min(columnHeights))
left = shortestColumn * (columnWidth + gap)
top = columnHeights[shortestColumn]
columnHeights[shortestColumn] += pin.height + gap
```

## Data Contract

```ts
type Pin = {

  alt: string;
```

## Performance Notes

- Use `ResizeObserver` to measure the feed container.
- Use `IntersectionObserver` for sentinel pagination.
- Preload images before painting them into the positioned list.
- Keep mutable pagination and image-loaded flags in refs.
- Add virtualization when DOM size becomes expensive.

## Accessibility Notes

- Every image needs useful `alt` text from the API or content pipeline.
- Keyboard users should be able to tab through pins in feed order.
- Loading state should not repeatedly announce noisy updates.
- Pin detail navigation should preserve scroll position when users return to the feed.

## Tradeoffs

Absolute positioning gives precise layout control but requires manual container height management. CSS columns are simpler but make ordering, measurement, and pagination harder to reason about.
